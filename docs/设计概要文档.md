# ABSeek 开发设计文档

> 新闻信息汇总工具：采集新闻 → 整理为简讯 → 人工调整 → 模板化图片导出

## 一、项目概述

### 1.1 定位

本地化的新闻信息汇总工具，将采集到的新闻整理为结构化简讯，通过可视化前端进行人工调整，最终基于模板生成适合移动端浏览的单页图片，用于社交网络发布。

### 1.2 核心特点

- **本地优先**：数据采集、存储、处理、图片生成全部在本地完成，无需服务器
- **外部 Agent 友好**：简讯以 Markdown 文件落地，外部 agent 工具可直接读写
- **模板化图片**：HTML/CSS 模板 + Puppeteer 截图，所见即所得
- **无外部服务**：不依赖 Docker、数据库，一个 Electron 进程全包

### 1.3 典型场景

以游戏新闻为例：

1. 用户配置多个游戏新闻网站（IGN、Eurogamer、Polygon 等）
2. 工具定时采集，将信息分别保存为多条简讯
3. 外部 agent 工具通过本地文件对简讯进行数据处理（分类、打标签等）
4. 前端可视化展示多条简讯信息，用户可二次调整
5. 用户选择模板 + 筛选属性，按属性值将简讯分流到对应模板
6. 批量导出多张模板图片，用于社交网络发布

### 1.4 合规说明

本工具仅用于个人信息整理，请遵守目标网站的服务条款与 robots 协议：

- 优先使用 RSS；
- 控制采集频率，不绕过登录；
- 不破解付费墙；
- 合理设置 User-Agent。

## 二、技术决策

### 2.1 已确认决策

| 项        | 决策                          | 说明                        |
| -------- | --------------------------- | ------------------------- |
| 运行形态     | Electron 桌面应用               | 数据天然本地，内置 Chromium 可复用于截图 |
| 前端       | React + Vite + TypeScript   | 组件化                       |
| 后端       | Node.js（Electron 主进程）       | 文件 IO、采集、截图、规则引擎          |
| 图片生成     | HTML/CSS → Puppeteer 截图     | 模板即网页                     |
| Agent 实现 | 外部工具直接处理本地 md 文件            | 应用不强绑定任何 LLM              |
| 存储格式     | Markdown + YAML frontmatter | 外部 agent 友好               |
| 采集方式     | 原生 RSS 优先 + 静态爬虫兜底          | 不引入 RSSHub                |
| 网络代理     | 本机 Clash 默认 127.0.0.1:7890  | 支持 none/system/manual     |

### 2.3 为什么不用 RSSHub / Docker / 数据库

- **不用 RSSHub**：海外游戏大站多自带原生 RSS，RSSHub 增量价值有限；自部署仍需本机能访问海外站，不解决核心问题
- **不用 Docker**：单进程 Electron 全包，避免多服务维护负担
- **不用数据库**：简讯以文件落地，外部 agent 需直接读写，数据库会形成黑盒

### 2.4 为什么用 Markdown 而不是纯 JSON

- 改属性 = 改 frontmatter；改正文 = 改 body
- 一个文件 = 一条简讯，粒度清晰
- 外部 LLM 天然擅长读写 Markdown
- 应用侧用 `gray-matter` 可靠解析

```
├── output/
│   ├── images/               # 生成的图片
│   └── history.json          # 导出历史
└── logs/                     # 日志（按天滚动）
```

### 4.2 简讯文件命名规则

```
{seq}-{source}-{slug}-{hash6}.md
```

例如：

```
01-ign-black-myth-wukong-dlc-a1b2c3.md
```

| 部分       | 说明                         |
| -------- | -------------------------- |
| `seq`    | 当天序号，如 01、02               |
| `source` | 来源 ID，如 ign、eurogamer      |
| `slug`   | 标题简化后的可读 slug              |
| `hash6`  | 根据 sourceUrl 或标题生成的 6 位短哈希 |

`id` 字段与文件名一致（不含 `.md`）。

### 4.3 简讯文件格式（Markdown + frontmatter）

```markdown
---

title: 黑神话悟空新DLC公布
summary: 游戏科学宣布《黑神话：悟空》将于年底推出新DLC，包含全新剧情与角色。
originalTitle: Black Myth: Wukong DLC Announced
originalSummary: Game Science announced...
date: 2026-07-23T08:00:00+08:00
source: IGN
sourceUrl: https://...
author: IGN Editorial
image: https://.../cover.jpg
tags: [游戏, DLC, 国产]
category: 游戏

  importance: high

```

### 4.4 字段说明

| 字段              | 类型               | 说明                  |
| --------------- | ---------------- | ------------------- |
| id              | string           | 与文件名一致              |
| title           | string           | 标题（可能被 agent 翻译）    |
| summary         | string           | 用于模板展示的精简摘要         |
| originalTitle   | string           | 原始标题，可选（便于校对）       |
| originalSummary | string           | 原始摘要，可选             |
| date            | datetime ISO8601 | 发布日期                |
| source          | string           | 信息来源                |
| sourceUrl       | string           | 原文链接                |
| author          | string           | 作者，可选               |
| image           | string           | 封面图 URL，可选          |
| tags            | string[]         | 标签数组                |
| category        | string           | 分类                  |
| aspect          | string           | 简讯的分类属性（如 `"A"`/`"B"`），用于默认绑定到模板；不与模板硬绑定，最终用哪个模板由 playlist 决定（已从 `customAttrs` 提升为顶层字段） |
| customAttrs     | object           | 自定义属性，键值受 schema 约束（`aspect` 不再放此处） |
| status          | enum             | 见 4.5               |
| agentMeta       | object           | 外部 agent 处理元信息      |

### 4.5 status 状态机

```
raw | processed | reviewed | exported | archived | ignored | excluded
```

| 状态          | 说明                |
| ----------- | ----------------- |
| `raw`       | 刚采集入库，未处理         |
| `processed` | 外部 Agent 或规则引擎已处理 |
| `reviewed`  | 人工已审核             |
| `exported`  | 已导出图片             |
| `archived`  | 归档，不参与默认展示        |
| `ignored`   | 忽略，不删除但不参与导出      |
| `excluded`  | 用户排除，不在列表显示，但仍参与去重（v0.9 新增） |

状态流转：

```
raw ──(agent/规则)──> processed ──(人工)──> reviewed ──(导出)──> exported
                                                              │
                                           任意状态可标记为 archived / ignored / excluded
                                           excluded 可恢复为 raw（前端「恢复显示」按钮）
```

**excluded 特殊处理**（v0.9）：

- `BriefRepo.list()` 默认过滤 `status='excluded'`，前端列表不显示
- `BriefRepo.listAll()` 返回全部（含 excluded），用于 `buildDedupIndex` 去重索引
- 前端「显示已排除」开关开启时调用 `list(true)` 显示全部，已排除项用灰色+删除线样式
- 文件名、目录结构不变，仅 frontmatter `status` 字段变化

### 4.6 customAttrs schema 规范

在 `settings.json` 中定义可用属性，避免键名/值失控：

```json
{
  "customAttrSchema": [
    {
      "key": "面",
      "label": "版面",
      "type": "enum",
      "values": ["A", "B", "C"],
      "required": false
    },
    {
      "key": "importance",
      "label": "重要性",
      "type": "enum",
      "values": ["high", "medium", "low"],
      "required": false
    }
  ]
}
```

约束：键名固定、值为短字符串、不嵌套对象、不使用数组、不使用特殊符号。

### 4.8 去重策略

#### 第一级：URL 规范化

去除：`utm_*`、`fbclid`、`ref`、`source`、`track`、`tracking`
统一：`http → https`、去末尾 `/`

#### 第二级：内容哈希

```
hash(title + summary + source)
```

#### 第三级：标题相似度

归一化（小写化、去标点、去停用词）后比较，相似度高于阈值判重。

默认 TTL：30 天。

### 4.9 模板配置格式

```
templates/templateA/
├── index.html
├── style.css
├── mock.json              # 模板预览假数据
└── config.json
```

**config.json**：

```json
{
  "id": "template-a",
  "name": "模板A-重磅资讯",
  "version": "1.0.0",
  "layout": {
    "aspectRatio": "9:16",
    "width": 1080,
    "height": 1920,
    "scale": 2
  },
  "limit": {
    "maxBriefs": 5,
    "overflowStrategy": "paginate"
  },
  "sort": [
    { "field": "customAttrs.importance", "order": "desc" },
    { "field": "date", "order": "desc" }
  ],
  "output": {
    "format": "jpg",
    "quality": 90,
    "filename": "{{date}}-{{templateId}}-{{aspect}}-{{page}}-{{lang}}.jpg"
  }
}
```

**overflowStrategy**：

| 策略         | 说明            |
| ---------- | ------------- |
| `truncate` | 只保留前 N 条      |
| `paginate` | 自动分页生成多张图（默认） |
| `shrink`   | 自动缩小字号或间距     |

**纯视觉资源**：模板不再含 `match` 字段，绑定关系集中在 `default-bindings.json`（见 4.10）与 playlist（见 七、Playlist 出图方案）中决定。`output.filename` 增加 `{{aspect}}`、`{{lang}}` 占位符，避免同模板渲染多 aspect / 多语言时文件名冲突。

### 4.10 default-bindings.json

位置：`data/config/default-bindings.json`

作用：定义 `aspect` 到 `templateId` 的默认绑定。创建 playlist 时按此自动分配（每个 aspect 对应哪个模板）。模板 config 不再含 `match.aspect`，绑定关系集中在此文件。

```json
{
  "bindings": [
    { "aspect": "A", "templateId": "template-a" },
    { "aspect": "B", "templateId": "template-b" }
  ]
}
```

## 五、核心模块设计

### 5.1 采集模块（v0.8 已实现）

实现位置：[electron/main/collector/](file:///d:/LFolder/AIProgram/ABSeek/electron/main/collector)

| 文件                          | 职责                                        |
| --------------------------- | ----------------------------------------- |
| `collector.ts`              | 编排：拉取 → 规则引擎 → 三级去重 → 入库                  |
| `rssAdapter.ts`             | rss-parser 拉取 + 字段映射                       |
| `crawlerAdapter.ts`         | cheerio 静态爬虫                              |
| `scheduler.ts`              | node-cron 注册/注销/reload，runtime 状态持久化       |
| `dedup.ts`                  | URL 规范化 / 内容哈希 / 标题相似度                    |
| `proxy.ts`                  | none/system/manual 代理模式封装                 |
| `types.ts`                  | RawBrief / CollectResult / TestConnectionResult |

#### 5.1.1 适配器架构

```typescript
interface Collector {
  type: 'rss' | 'crawler-static' | 'crawler-dynamic';
  collect(source: SourceConfig): Promise<RawBrief[]>;
}
```

#### 5.1.2 三种适配器

| 类型              | 实现                   | 状态                                  |
| --------------- | -------------------- | ----------------------------------- |
| rss             | rss-parser           | **已实现**（默认首选）                       |
| crawler-static  | cheerio + node-fetch | **已实现**（兜底）                         |
| crawler-dynamic | playwright           | **可选扩展，默认不启用，阶段后期按需引入** |

阶段 1/2 不引入 Playwright，避免浏览器版本过多。

#### 5.1.3 代理接入

支持三种模式：

- `none`：不使用代理
- `system`：使用系统代理
- `manual`：手动配置（http/socks5）

#### 5.3.1 文件监听策略（已实现，见 [watcher.ts](file:///d:/LFolder/AIProgram/ABSeek/electron/main/store/watcher.ts)）

- **防抖**：`onBatchChanged` 在文件变化后聚合触发，避免抖动

  前端只更新对应条目，不刷新整个列表。

## 六、核心流程

### 6.1 采集到导出的完整链路

```
[采集] node-cron 定时触发
   ↓ rss-parser / cheerio 拉取（带 timeout/retry/代理）
[去重] URL 规范化 + 内容哈希 + 标题相似度
[入库] 写 data/briefs/{date}/{id}.md (status: raw)
   ↓
[规则引擎] HTML 清理、日期标准化、默认标签、关键词打标
   ↓
[外部 Agent] agent 工具扫描当天 md 文件
   → 生成 summary、判定 aspect = A/B
   → 先写 .tmp 再重命名
   ↓
[文件监听] chokidar debounce + 校验 → 增量通知前端
   ↓
[前端调整] 用户可视化校对、修正个别分类/属性
   ↓
[图片生成] 创建 playlist（按 default-bindings.json 自动分配 aspect → 模板）
   → 简讯[aspect=A] → 模板A 图（分页）
   → 简讯[aspect=B] → 模板B 图（分页）
[导出] output/images/ + history.json
```

### 6.2 外部 Agent 协作机制

应用与外部 agent 的边界：

- **应用职责**：采集、去重、入库、规则引擎、文件监听、前端展示、图片生成
- **外部 agent 职责**：深度摘要、智能分类、属性归一化、翻译、任何需要 LLM 的处理

协作方式：应用把简讯落地为 md 文件 → 外部 agent 读写 md → chokidar 监听变化 → 前端增量刷新。应用不耦合任何 LLM。

## 七、Playlist 出图方案

> Playlist 是一次出图任务的完整状态文件，类比 PSD 工程文件：它聚合了「哪些简讯、用哪个模板、每个模板下分类了哪些简讯、显式顺序、输出语言」。

### 7.1 定位与职责

Playlist 是聚合层，与简讯、模板的关系如下：

| 实体 | 角色 | 可变性 |
| --- | --- | --- |
| 简讯（Brief） | 数据源 | 只读（内容可被 agent/人工编辑，但 playlist 不改它） |
| 模板（Template） | 视觉规则 | 只读（纯视觉资源，不含 match） |
| Playlist | 聚合层 | 可编辑、可复用 |

Playlist 承载：哪些简讯、用哪个模板、每个模板下分类了哪些简讯、显式顺序、输出语言。

### 7.2 存储位置与命名

- 目录：`data/playlists/`
- 文件名：`{YYYYMMDD}-{seq}-{slug}.json`，如 `20260724-01-game-news.json`

### 7.3 Playlist 结构

```json
{
  "id": "20260724-01-game-news",
  "name": "2026-07-24 游戏资讯日常合集",
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "templates": [
    {
      "templateId": "template-a",
      "forAspect": "A",
      "briefIds": ["20260724-01-...", "20260723-02-..."]
    }
  ],
  "output": {
    "lang": ["zh", "en"],
    "format": "jpg",
    "quality": 90
  }
}
```

### 7.4 关键规则

- **简讯顺序由 `playlist.briefIds` 决定**（显式数组顺序）
- **模板 `config.sort` 规则仅在「创建 playlist 时」用一次生成默认顺序**，之后不再生效
- **同一模板可在 playlist 出现多次**（如节日场景 `template-c` 同时渲染 aspect A 和 B）
- **去掉了 override 机制**：要改某条简讯的 aspect，直接改简讯 md 文件的 `aspect` 字段
- 创建 playlist 时，按 `default-bindings.json`（见 4.10）自动把每个 aspect 的简讯分配到对应模板

## 八、外部 Agent 协作规范

应用首次初始化时生成 `data/AGENT_GUIDE.md`，规范如下：

### 8.1 可读写目录

- `data/briefs/{date}/*.md` — 简讯文件，可读写
- `data/AGENT_GUIDE.md` — 本规范（只读）

### 8.2 可修改字段

```yaml
title / summary / tags / category / customAttrs / status / agentMeta
originalTitle / originalSummary
```

### 8.3 不可修改字段

```yaml
id / source / sourceUrl / date
```

（除非明确在做数据纠错）

### 8.4 写入方式

**必须先写临时文件再重命名**，避免应用读到半截文件：

```
xxx.md.tmp  →  写入完成  →  rename  →  xxx.md
```

### 8.5 状态流转规则

```
raw → processed（agent 处理后置此状态）
```

人工审核、导出由应用或用户操作，agent 不应主动置为 reviewed/exported。

### 8.6 YAML 格式要求

- 所有时间用 ISO 8601
- tags 必须是数组
- customAttrs 必须是扁平对象，键名受 schema 约束
- 不使用特殊符号

### 8.7 agentMeta 要求

```yaml
agentMeta:
  processedAt: 2026-07-23T08:05:00+08:00
  tool: external-llm
  model: qwen3.8           # 可选
  version: 1              # 规则/prompt 版本
  changes: [summary, category, customAttrs]
  notes: 自动判定为 A 面
```

### 8.8 示例

见 4.3 简讯文件格式。

### 8.9 错误处理约定

- 写入前校验 YAML 合法性
- 不要删除 `id` / `source` / `date` 字段
- 若数据有误，置 `status: ignored` 并在 `agentMeta.notes` 说明

## 九、错误处理与日志

### 9.1 统一 IPC 返回格式

```ts
type Result<T> =
  | { success: true; data: T }
  | { success: false; error: AppError };

interface AppError {
  code: string;
  message: string;
  detail?: unknown;
}
```

示例：

```json
{
  "success": false,
  "error": {
    "code": "COLLECT_TIMEOUT",
    "message": "采集超时",
    "detail": { "sourceId": "ign", "timeoutMs": 15000 }
  }
}
```

### 9.2 错误码

```
PROXY_UNAVAILABLE
RSS_FETCH_FAILED
RSS_PARSE_FAILED
CRAWLER_SELECTOR_INVALID
BRIEF_PARSE_FAILED
TEMPLATE_NOT_FOUND
SCREENSHOT_FAILED
OUTPUT_WRITE_FAILED
```

### 9.3 日志

```
data/logs/
├── app-2026-07-24.log
├── collector-2026-07-24.log
├── watcher-2026-07-24.log
└── renderer-2026-07-24.log
```

| 模块        | 日志内容            |
| --------- | --------------- |

| renderer  | 模板加载、截图成功、导出失败  |

按天滚动。

### 9.4 失败处理

- 采集失败：更新 `runtime.consecutiveFailures`，写日志，前端告警
- 文件解析失败：移入 `data/_invalid/`，前端提示
- 截图失败：返回 `SCREENSHOT_FAILED`，保留中间 HTML 便于排查

| 网络依赖          | fixtures 离线样本，不依赖网络                                          |

### 16.3 运行方式

```bash
npm run test          # 单次跑全部测试
npm run test:watch    # 监听模式
npm run test -- tests/unit/dedup.test.ts   # 跑单个文件
```

### 16.4 已踩过的坑

- **YAML 序列化 undefined**：`BriefRepo.toFrontmatter` 早期未过滤 undefined，js-yaml `safeDump` 抛 `YAMLException`。修复方式：遍历字段只保留非 undefined 值。
- **mock 状态污染**：`mockClear` 只清调用次数，不清 `mockReturnValue` 设置。改用 `mockReset` + 显式重新设置默认返回值。
- **`vi.mock` 提升顺序**：`vi.mock` 在文件顶部被提升执行，引用外部变量会报 `Cannot access before initialization`。用 `vi.hoisted` 把 mock 函数提升到同一阶段。
