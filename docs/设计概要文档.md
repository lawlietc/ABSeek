# ABSeek 开发设计文档

> 新闻信息汇总工具：采集新闻 → 整理为简讯 → 人工调整 → 模板化图片导出

## 一、项目概述

### 1.1 定位

本地化的新闻信息汇总工具，将采集到的新闻整理为结构化简讯，通过可视化前端进行人工调整，最终基于模板生成适合移动端浏览的单页图片，用于社交网络发布。

### 1.2 核心特点

- **本地优先**：数据采集、存储、处理、图片生成全部在本地完成，无需服务器
- **外部 Agent 友好**：简讯以 Markdown 文件落地，外部 agent 工具可直接读写
- **模板化图片**：HTML/CSS 模板 + Puppeteer 截图，所见即所得
- **无外部服务**：不依赖 Docker、数据库，一个 Electron 进程全包

### 1.3 典型场景

以游戏新闻为例：

1. 用户配置多个游戏新闻网站（IGN、Eurogamer、Polygon 等）
2. 工具定时采集，将信息分别保存为多条简讯
3. 外部 agent 工具通过本地文件对简讯进行数据处理（分类、打标签等）
4. 前端可视化展示多条简讯信息，用户可二次调整
5. 用户选择模板 + 筛选属性，按属性值将简讯分流到对应模板
6. 批量导出多张模板图片，用于社交网络发布

### 1.4 合规说明

本工具仅用于个人信息整理，请遵守目标网站的服务条款与 robots 协议：

- 优先使用 RSS；
- 控制采集频率，不绕过登录；
- 不破解付费墙；
- 合理设置 User-Agent。

## 二、技术决策

### 2.1 已确认决策

| 项        | 决策                          | 说明                        |
| -------- | --------------------------- | ------------------------- |
| 运行形态     | Electron 桌面应用               | 数据天然本地，内置 Chromium 可复用于截图 |
| 前端       | React + Vite + TypeScript   | 组件化                       |
| 后端       | Node.js（Electron 主进程）       | 文件 IO、采集、截图、规则引擎          |
| 图片生成     | HTML/CSS → Puppeteer 截图     | 模板即网页                     |
| Agent 实现 | 外部工具直接处理本地 md 文件            | 应用不强绑定任何 LLM              |
| 存储格式     | Markdown + YAML frontmatter | 外部 agent 友好               |
| 采集方式     | 原生 RSS 优先 + 静态爬虫兜底          | 不引入 RSSHub                |
| 网络代理     | 本机 Clash 默认 127.0.0.1:7890  | 支持 none/system/manual     |

### 2.2 补充决策表（已采纳）

| 编号  | 问题          | 决策                                                           |
| --- | ----------- | ------------------------------------------------------------ |
| 1   | 文件命名        | `{seq}-{source}-{slug}-{hash6}.md`                           |
| 2   | `id` 规则     | 与文件名一致，不含 `.md`                                              |
| 3   | 摘要字段        | 新增 `summary` 字段                                              |
| 4   | 模板变量        | 使用 `{{summary}}`，弃用 `{{description}}`                        |
| 5   | 状态字段        | `raw / processed / reviewed / exported / archived / ignored` |
| 6   | 时间格式        | 统一 ISO 8601，如 `2026-07-24T08:00:00+08:00`                    |
| 7   | 去重策略        | URL 规范化 + 内容哈希 + 标题相似度                                       |
| 8   | 去重 TTL      | 默认 30 天                                                      |
| 9   | 外部 Agent 规范 | 提供 `data/AGENT_GUIDE.md`                                     |
| 10  | Agent 写入方式  | 先写 `.tmp`，再重命名                                               |
| 11  | 文件监听        | debounce 300~500ms，忽略临时文件                                    |
| 12  | 用户编辑保护      | 编辑中文件被外部修改时提示用户                                              |
| 13  | 代理配置        | 支持 none / system / manual                                    |
| 14  | 默认代理        | 默认 `http://127.0.0.1:7890`，可关闭                               |
| 15  | 动态爬虫        | 阶段 1/2 不引入 Playwright                                        |
| 16  | 截图浏览器       | **已验证**：puppeteer + 系统已装 Chrome 路径自动探测，无需下载 puppeteer 自带 Chromium |
| 17  | 模板超限        | 默认 `paginate` 分页生成多张图                                        |
| 18  | 图片格式        | 默认 JPG，quality 90                                            |
| 19  | 图片尺寸        | 1080x1920，scale=2                                            |
| 20  | 字体          | PingFang SC / Microsoft YaHei / Noto Sans CJK SC             |
| 21  | 规则引擎        | 阶段 3 引入最小规则引擎                                                |
| 22  | 日志          | 新增 `data/logs/`                                              |
| 23  | 生产数据目录      | `app.getPath('userData')/data/`                              |
| 24  | 模板目录        | 内置模板 + 用户模板                                                  |
| 25  | 错误返回        | 统一 `Result<T>` 格式                                            |
| 26  | 排序策略        | 默认 sort + `playlist.briefIds` 显式顺序 + title 兜底稳定排序          |
| 27  | 人工调整顺序      | 拖拽调序时直接重写 `playlist.briefIds` 数组                            |
| 28  | 跨模板移动简讯    | 直接改简讯 md 文件的 `aspect` 字段（去掉 override 机制）                 |

### 2.3 为什么不用 RSSHub / Docker / 数据库

- **不用 RSSHub**：海外游戏大站多自带原生 RSS，RSSHub 增量价值有限；自部署仍需本机能访问海外站，不解决核心问题
- **不用 Docker**：单进程 Electron 全包，避免多服务维护负担
- **不用数据库**：简讯以文件落地，外部 agent 需直接读写，数据库会形成黑盒

### 2.4 为什么用 Markdown 而不是纯 JSON

- 改属性 = 改 frontmatter；改正文 = 改 body
- 一个文件 = 一条简讯，粒度清晰
- 外部 LLM 天然擅长读写 Markdown
- 应用侧用 `gray-matter` 可靠解析

## 三、系统架构

### 3.1 整体架构

```
┌──────────────────────────────────────────────────────┐
│              Electron 桌面应用 (ABSeek)               │
│                                                      │
│  ┌──────────── 前端 (React + Vite) ─────────────┐    │
│  │  简讯管理 │ 采集配置 │ 模板预览 │ 图片工作室 │    │
│  └──────────────────┬───────────────────────────┘    │
│                     │ IPC (Result<T>)                │
│  ┌──────────────────┴───────────────────────────┐    │
│  │            后端 (Electron 主进程)             │    │
│  │  ┌─────────┐ ┌──────────┐ ┌──────────────┐  │    │
│  │  │采集调度 │ │规则引擎  │ │图片渲染      │  │    │
│  │  │ rss     │ │(最小规则)│ │ Puppeteer    │  │    │
│  │  │ cheerio │ └──────────┘ │ HTML→截图    │  │    │
│  │  └────┬────┘       ↑      └──────┬───────┘  │    │
│  │       │       外部 Agent 工具     │          │    │
│  │       │       (读写 md 文件)      │          │    │
│  │       ↓             ↑             ↓          │    │
│  │  ┌──────────────────────────────────────┐   │    │
│  │  │   chokidar 监听(debounce+校验)→ 增量  │   │    │
│  │  │   本地存储 (data/briefs/*.md)        │   │    │
│  │  └──────────────────────────────────────┘   │    │
│  └──────────────────────────────────────────────┘    │
└──────────────────────┬───────────────────────────────┘
                       │ HTTP (走 Clash 代理)
                       ↓
              海外游戏资讯网站 (RSS/HTML)
```

### 3.2 模块划分

| 模块     | 职责                            | 技术实现                              |
| ------ | ----------------------------- | --------------------------------- |
| 采集调度器  | 定时触发采集任务，管理采集源                | node-cron                         |
| 采集适配器  | RSS / 静态爬虫 / 动态爬虫（可选）         | rss-parser / cheerio / playwright |
| 规则引擎   | 内置最小规则：默认标签、分类、HTML 清理、日期标准化  | 自研轻量规则                            |
| 存储层    | 简讯读写、去重、schema 校验             | gray-matter                       |
| 文件监听   | debounce + 临时文件忽略 + 校验 + 增量通知 | chokidar                          |
| 图片渲染   | 模板填充 → HTML → 截图（分页）          | Puppeteer                         |
| IPC 通信 | 前后端通信，统一 Result<T>            | Electron ipcMain/ipcRenderer      |
| 日志     | 按天滚动，分模块                      | winston 或自写                       |

## 四、数据模型

### 4.1 存储结构

```
data/
├── config/
│   ├── sources.json          # 采集源配置（含 runtime 状态）
│   ├── templates.json        # 模板注册表
│   └── settings.json         # 全局设置（代理、去重、customAttrSchema）
├── briefs/
│   └── 2026-07-23/           # 按日期分目录
│       ├── 01-ign-black-myth-wukong-dlc-a1b2c3.md
│       └── 02-eurogamer-xxx-d4e5f6.md
├── _invalid/                 # 解析失败的异常文件
├── AGENT_GUIDE.md            # 外部 Agent 协作规范
├── templates/                # 用户模板（HTML/CSS）
├── output/
│   ├── images/               # 生成的图片
│   └── history.json          # 导出历史
└── logs/                     # 日志（按天滚动）
```

### 4.2 简讯文件命名规则

```
{seq}-{source}-{slug}-{hash6}.md
```

例如：

```
01-ign-black-myth-wukong-dlc-a1b2c3.md
```

| 部分       | 说明                         |
| -------- | -------------------------- |
| `seq`    | 当天序号，如 01、02               |
| `source` | 来源 ID，如 ign、eurogamer      |
| `slug`   | 标题简化后的可读 slug              |
| `hash6`  | 根据 sourceUrl 或标题生成的 6 位短哈希 |

`id` 字段与文件名一致（不含 `.md`）。

### 4.3 简讯文件格式（Markdown + frontmatter）

```markdown
---
id: 01-ign-black-myth-wukong-dlc-a1b2c3
title: 黑神话悟空新DLC公布
summary: 游戏科学宣布《黑神话：悟空》将于年底推出新DLC，包含全新剧情与角色。
originalTitle: Black Myth: Wukong DLC Announced
originalSummary: Game Science announced...
date: 2026-07-23T08:00:00+08:00
source: IGN
sourceUrl: https://...
author: IGN Editorial
image: https://.../cover.jpg
tags: [游戏, DLC, 国产]
category: 游戏
aspect: A
customAttrs:
  importance: high
status: processed
agentMeta:
  processedAt: 2026-07-23T08:05:00+08:00
  tool: external-llm
  model: qwen3.8
  version: 1
  changes: [summary, category, aspect, customAttrs]
  notes: 自动判定为 A 面
---

这里是原始正文或长正文，供 agent 处理与人工参考。
```

### 4.4 字段说明

| 字段              | 类型               | 说明                  |
| --------------- | ---------------- | ------------------- |
| id              | string           | 与文件名一致              |
| title           | string           | 标题（可能被 agent 翻译）    |
| summary         | string           | 用于模板展示的精简摘要         |
| originalTitle   | string           | 原始标题，可选（便于校对）       |
| originalSummary | string           | 原始摘要，可选             |
| date            | datetime ISO8601 | 发布日期                |
| source          | string           | 信息来源                |
| sourceUrl       | string           | 原文链接                |
| author          | string           | 作者，可选               |
| image           | string           | 封面图 URL，可选          |
| tags            | string[]         | 标签数组                |
| category        | string           | 分类                  |
| aspect          | string           | 简讯的分类属性（如 `"A"`/`"B"`），用于默认绑定到模板；不与模板硬绑定，最终用哪个模板由 playlist 决定（已从 `customAttrs` 提升为顶层字段） |
| customAttrs     | object           | 自定义属性，键值受 schema 约束（`aspect` 不再放此处） |
| status          | enum             | 见 4.5               |
| agentMeta       | object           | 外部 agent 处理元信息      |

### 4.5 status 状态机

```
raw | processed | reviewed | exported | archived | ignored
```

| 状态          | 说明                |
| ----------- | ----------------- |
| `raw`       | 刚采集入库，未处理         |
| `processed` | 外部 Agent 或规则引擎已处理 |
| `reviewed`  | 人工已审核             |
| `exported`  | 已导出图片             |
| `archived`  | 归档，不参与默认展示        |
| `ignored`   | 忽略，不删除但不参与导出      |

状态流转：

```
raw ──(agent/规则)──> processed ──(人工)──> reviewed ──(导出)──> exported
                                                              │
                                           任意状态可标记为 archived / ignored
```

### 4.6 customAttrs schema 规范

在 `settings.json` 中定义可用属性，避免键名/值失控：

```json
{
  "customAttrSchema": [
    {
      "key": "面",
      "label": "版面",
      "type": "enum",
      "values": ["A", "B", "C"],
      "required": false
    },
    {
      "key": "importance",
      "label": "重要性",
      "type": "enum",
      "values": ["high", "medium", "low"],
      "required": false
    }
  ]
}
```

约束：键名固定、值为短字符串、不嵌套对象、不使用数组、不使用特殊符号。

### 4.8 去重策略

#### 第一级：URL 规范化

去除：`utm_*`、`fbclid`、`ref`、`source`、`track`、`tracking`
统一：`http → https`、去末尾 `/`

#### 第二级：内容哈希

```
hash(title + summary + source)
```

#### 第三级：标题相似度

归一化（小写化、去标点、去停用词）后比较，相似度高于阈值判重。

默认 TTL：30 天。

### 4.9 模板配置格式

```
templates/templateA/
├── index.html
├── style.css
├── mock.json              # 模板预览假数据
└── config.json
```

**config.json**：

```json
{
  "id": "template-a",
  "name": "模板A-重磅资讯",
  "version": "1.0.0",
  "layout": {
    "aspectRatio": "9:16",
    "width": 1080,
    "height": 1920,
    "scale": 2
  },
  "limit": {
    "maxBriefs": 5,
    "overflowStrategy": "paginate"
  },
  "sort": [
    { "field": "customAttrs.importance", "order": "desc" },
    { "field": "date", "order": "desc" }
  ],
  "output": {
    "format": "jpg",
    "quality": 90,
    "filename": "{{date}}-{{templateId}}-{{aspect}}-{{page}}-{{lang}}.jpg"
  }
}
```

**overflowStrategy**：

| 策略         | 说明            |
| ---------- | ------------- |
| `truncate` | 只保留前 N 条      |
| `paginate` | 自动分页生成多张图（默认） |
| `shrink`   | 自动缩小字号或间距     |

**纯视觉资源**：模板不再含 `match` 字段，绑定关系集中在 `default-bindings.json`（见 4.10）与 playlist（见 七、Playlist 出图方案）中决定。`output.filename` 增加 `{{aspect}}`、`{{lang}}` 占位符，避免同模板渲染多 aspect / 多语言时文件名冲突。

### 4.10 default-bindings.json

位置：`data/config/default-bindings.json`

作用：定义 `aspect` 到 `templateId` 的默认绑定。创建 playlist 时按此自动分配（每个 aspect 对应哪个模板）。模板 config 不再含 `match.aspect`，绑定关系集中在此文件。

```json
{
  "bindings": [
    { "aspect": "A", "templateId": "template-a" },
    { "aspect": "B", "templateId": "template-b" }
  ]
}
```

## 五、核心模块设计

### 5.1 采集模块

#### 5.1.1 适配器架构

```typescript
interface Collector {
  type: 'rss' | 'crawler-static' | 'crawler-dynamic';
  collect(source: SourceConfig): Promise<RawBrief[]>;
}
```

#### 5.1.2 三种适配器

| 类型              | 实现                   | 状态                      |
| --------------- | -------------------- | ----------------------- |
| rss             | rss-parser           | **默认首选**                |
| crawler-static  | cheerio + node-fetch | **兜底**                  |
| crawler-dynamic | playwright           | **可选扩展，默认不启用，阶段后期按需引入** |

阶段 1/2 不引入 Playwright，避免浏览器版本过多。

#### 5.1.3 代理接入

支持三种模式：

- `none`：不使用代理
- `system`：使用系统代理
- `manual`：手动配置（http/socks5）

rss-parser / node-fetch 通过 `https-proxy-agent` 注入；playwright launch 传 `proxy.server`。设置页提供"测试代理连通性"。

#### 5.1.4 采集源运行状态

每次采集后更新 `runtime`：lastRunAt / lastSuccessAt / lastError / consecutiveFailures / lastCollectedCount / lastNewCount。

#### 5.1.5 手动测试采集

采集配置页提供"测试连接 / 试采集"，返回：

```json
{
  "success": true,
  "fetched": 20,
  "sample": [{ "title": "...", "link": "...", "date": "..." }]
}
```

#### 5.1.6 采集流程

```
1. node-cron 触发
2. 按 source.type 选适配器
3. 适配器拉取 → RawBrief[]（带 timeout/retry）
4. URL 规范化 + 去重
5. 应用 defaultTags / defaultCategory
6. 规则引擎：HTML 清理、日期标准化、关键词打标
7. 写 data/briefs/{date}/{id}.md (status: raw)
8. 更新 source.runtime
9. 写采集日志
```

### 5.2 规则引擎（最小实现，阶段 3 引入）

负责确定性、轻量处理：

- defaultTags / defaultCategory 应用
- HTML 实体清理
- 日期标准化（统一 ISO 8601）
- 简单关键词分类打标

复杂处理（深度摘要、智能分类、翻译）交给外部 agent。

### 5.3 存储模块

```typescript
interface BriefRepo {
  save(brief: Brief): Promise<void>;
  get(id: string): Promise<Brief>;
  list(filter?: BriefFilter): Promise<Brief[]>;
  update(id: string, patch: Partial<Brief>): Promise<void>;
  delete(id: string): Promise<void>;
}
```

#### 5.3.1 文件监听策略

- **防抖**：300~500ms，文件停止变化后再读取解析
- **忽略临时文件**：`*.tmp`、`*.lock`、`*.partial`
- **schema 校验**：读取后校验 id / title / date / status / tags(数组) / customAttrs(对象)，失败不崩溃
- **异常文件处理**：解析失败移入 `data/_invalid/`，前端提示"发现 N 个无法解析的简讯"
- **增量通知**：分类事件
  
  ```ts
  onBriefAdded(cb: (brief: Brief) => void)
  onBriefUpdated(cb: (id: string, brief: Brief) => void)
  onBriefDeleted(cb: (id: string) => void)
  onBatchChanged(cb: () => void)
  ```
  
  前端只更新对应条目，不刷新整个列表。

#### 5.3.2 用户编辑保护

用户正在编辑某条简讯时，外部文件变化不直接覆盖：

- 标记 `isDirty`
- 提示"该简讯已被外部工具修改"
- 选项：保留本地编辑 / 重新加载文件 / 查看差异

### 5.4 图片渲染模块

#### 5.4.1 渲染流程

```
1. 用户选模板 + 选筛选属性键
2. 按 match.attr 不同值把简讯分组到对应模板
3. 每组按 sort 排序，按 maxBriefs 截断
4. overflowStrategy=paginate → 自动分页
5. Handlebars 填充模板 HTML
6. Puppeteer 按视口截图（width×scale）
7. 落盘 output/images/{filename}
8. 写 output/history.json
```

#### 5.4.2 模板变量

```hbs
{{#each briefs}}
<div class="brief-item">
  <h3>{{title}}</h3>
  <p class="desc">{{summary}}</p>
  <span class="source">{{source}} · {{formatDate date}}</span>
</div>
{{/each}}
```

注意：用 `{{summary}}`，不用 `{{description}}`。

#### 5.4.3 浏览器策略

- 开发阶段优先验证 Electron Chromium（puppeteer-core + connect 到 Electron）
- 若存在兼容问题，切换为 Chromium for Testing（puppeteer 完整版）
- 打包时明确浏览器路径与版本

#### 5.4.4 模板安全限制

渲染时禁用：远程 JS / 远程 CSS / 远程图片 / 未知协议 / 内联脚本。只允许本地资源（`file://`）。

## 六、核心流程

### 6.1 采集到导出的完整链路

```
[采集] node-cron 定时触发
   ↓ rss-parser / cheerio 拉取（带 timeout/retry/代理）
[去重] URL 规范化 + 内容哈希 + 标题相似度
[入库] 写 data/briefs/{date}/{id}.md (status: raw)
   ↓
[规则引擎] HTML 清理、日期标准化、默认标签、关键词打标
   ↓
[外部 Agent] agent 工具扫描当天 md 文件
   → 生成 summary、判定 aspect = A/B
   → 先写 .tmp 再重命名
   ↓
[文件监听] chokidar debounce + 校验 → 增量通知前端
   ↓
[前端调整] 用户可视化校对、修正个别分类/属性
   ↓
[图片生成] 创建 playlist（按 default-bindings.json 自动分配 aspect → 模板）
   → 简讯[aspect=A] → 模板A 图（分页）
   → 简讯[aspect=B] → 模板B 图（分页）
[导出] output/images/ + history.json
```

### 6.2 外部 Agent 协作机制

应用与外部 agent 的边界：

- **应用职责**：采集、去重、入库、规则引擎、文件监听、前端展示、图片生成
- **外部 agent 职责**：深度摘要、智能分类、属性归一化、翻译、任何需要 LLM 的处理

协作方式：应用把简讯落地为 md 文件 → 外部 agent 读写 md → chokidar 监听变化 → 前端增量刷新。应用不耦合任何 LLM。

## 七、Playlist 出图方案

> Playlist 是一次出图任务的完整状态文件，类比 PSD 工程文件：它聚合了「哪些简讯、用哪个模板、每个模板下分类了哪些简讯、显式顺序、输出语言」。

### 7.1 定位与职责

Playlist 是聚合层，与简讯、模板的关系如下：

| 实体 | 角色 | 可变性 |
| --- | --- | --- |
| 简讯（Brief） | 数据源 | 只读（内容可被 agent/人工编辑，但 playlist 不改它） |
| 模板（Template） | 视觉规则 | 只读（纯视觉资源，不含 match） |
| Playlist | 聚合层 | 可编辑、可复用 |

Playlist 承载：哪些简讯、用哪个模板、每个模板下分类了哪些简讯、显式顺序、输出语言。

### 7.2 存储位置与命名

- 目录：`data/playlists/`
- 文件名：`{YYYYMMDD}-{seq}-{slug}.json`，如 `20260724-01-game-news.json`

### 7.3 Playlist 结构

```json
{
  "id": "20260724-01-game-news",
  "name": "2026-07-24 游戏资讯日常合集",
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "templates": [
    {
      "templateId": "template-a",
      "forAspect": "A",
      "briefIds": ["20260724-01-...", "20260723-02-..."]
    }
  ],
  "output": {
    "lang": ["zh", "en"],
    "format": "jpg",
    "quality": 90
  }
}
```

### 7.4 关键规则

- **简讯顺序由 `playlist.briefIds` 决定**（显式数组顺序）
- **模板 `config.sort` 规则仅在「创建 playlist 时」用一次生成默认顺序**，之后不再生效
- **同一模板可在 playlist 出现多次**（如节日场景 `template-c` 同时渲染 aspect A 和 B）
- **去掉了 override 机制**：要改某条简讯的 aspect，直接改简讯 md 文件的 `aspect` 字段
- 创建 playlist 时，按 `default-bindings.json`（见 4.10）自动把每个 aspect 的简讯分配到对应模板

## 八、外部 Agent 协作规范

应用首次初始化时生成 `data/AGENT_GUIDE.md`，规范如下：

### 8.1 可读写目录

- `data/briefs/{date}/*.md` — 简讯文件，可读写
- `data/AGENT_GUIDE.md` — 本规范（只读）

### 8.2 可修改字段

```yaml
title / summary / tags / category / customAttrs / status / agentMeta
originalTitle / originalSummary
```

### 8.3 不可修改字段

```yaml
id / source / sourceUrl / date
```

（除非明确在做数据纠错）

### 8.4 写入方式

**必须先写临时文件再重命名**，避免应用读到半截文件：

```
xxx.md.tmp  →  写入完成  →  rename  →  xxx.md
```

### 8.5 状态流转规则

```
raw → processed（agent 处理后置此状态）
```

人工审核、导出由应用或用户操作，agent 不应主动置为 reviewed/exported。

### 8.6 YAML 格式要求

- 所有时间用 ISO 8601
- tags 必须是数组
- customAttrs 必须是扁平对象，键名受 schema 约束
- 不使用特殊符号

### 8.7 agentMeta 要求

```yaml
agentMeta:
  processedAt: 2026-07-23T08:05:00+08:00
  tool: external-llm
  model: qwen3.8           # 可选
  version: 1              # 规则/prompt 版本
  changes: [summary, category, customAttrs]
  notes: 自动判定为 A 面
```

### 8.8 示例

见 4.3 简讯文件格式。

### 8.9 错误处理约定

- 写入前校验 YAML 合法性
- 不要删除 `id` / `source` / `date` 字段
- 若数据有误，置 `status: ignored` 并在 `agentMeta.notes` 说明

## 九、错误处理与日志

### 9.1 统一 IPC 返回格式

```ts
type Result<T> =
  | { success: true; data: T }
  | { success: false; error: AppError };

interface AppError {
  code: string;
  message: string;
  detail?: unknown;
}
```

示例：

```json
{
  "success": false,
  "error": {
    "code": "COLLECT_TIMEOUT",
    "message": "采集超时",
    "detail": { "sourceId": "ign", "timeoutMs": 15000 }
  }
}
```

### 9.2 错误码

```
PROXY_UNAVAILABLE
RSS_FETCH_FAILED
RSS_PARSE_FAILED
CRAWLER_SELECTOR_INVALID
BRIEF_PARSE_FAILED
TEMPLATE_NOT_FOUND
SCREENSHOT_FAILED
OUTPUT_WRITE_FAILED
```

### 9.3 日志

```
data/logs/
├── app-2026-07-24.log
├── collector-2026-07-24.log
├── watcher-2026-07-24.log
└── renderer-2026-07-24.log
```

| 模块        | 日志内容            |
| --------- | --------------- |
| app       | 启动、退出、异常        |
| collector | 采集开始、成功、失败、新增数量 |
| watcher   | 文件变化、解析失败       |
| renderer  | 模板加载、截图成功、导出失败  |

按天滚动。

### 9.4 失败处理

- 采集失败：更新 `runtime.consecutiveFailures`，写日志，前端告警
- 文件解析失败：移入 `data/_invalid/`，前端提示
- 截图失败：返回 `SCREENSHOT_FAILED`，保留中间 HTML 便于排查

### 15.3 已知限制与待补项（v0.5）

- **拖拽调序未实现**：当前用复选框+按钮替代，后期可迭代 `react-dnd` / `@dnd-kit`
- **批量导出仅按当前选中**：不依赖 playlist 文件；如需复用历史出图配置，仍需走 playlist（`playlist:render` IPC 已通）
- **导出同日期会覆盖**：同一天多次导出会覆盖该日期子目录下同名文件（按 `{{date}}-{{templateId}}-{{aspect}}-{{page}}-{{lang}}.jpg` 命名）；如需保留历史，可后续加时间戳或导出批次号
- **编辑抽屉仅支持单条**：批量属性编辑（如批量改 aspect）已通过"移到 A/B 面"实现，但批量改 tags/category 尚未支持
- **无文件监听**：外部 agent 改 md 后前端不会自动刷新，需手动重启或重新加载列表
- **无 schema 校验**：保存简讯时不校验字段合法性
- **无日志系统**：错误仅 console.warn/error，未落盘
