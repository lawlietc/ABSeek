# ABSeek 产品需求文档（PRD）

> 新闻信息汇总工具 · 面向社交网络发布的本地化内容生产工具

## 一、产品概述

### 1.1 产品定位

ABSeek 是一款**本地化的新闻信息汇总工具**，帮助内容创作者将多源新闻采集、整理、人工调整后，快速生成适合移动端浏览的图片，用于社交网络发布。

**一句话描述**：把散落在各处的新闻，变成一张张可直接发布的精美资讯图。

### 1.2 目标用户

| 用户画像                | 典型场景                          |
| ------------------- | ----------------------------- |
| 社交平台内容创作者（微博/小红书/X） | 每日汇总游戏/科技/行业新闻，做成图文合集发布       |
| 信息整理爱好者             | 订阅大量 RSS，但苦于没有顺手的"再加工 + 出图"工具 |
| 自媒体/小号运营者           | 需要快速产出每日资讯轮播图                 |

### 1.3 用户痛点

| 痛点     | 现状                     | ABSeek 解决方式                  |
| ------ | ---------------------- | ---------------------------- |
| 信息分散   | 每天手动浏览多个网站，效率低         | 多源定时采集，自动汇总                  |
| 加工成本高  | 复制粘贴 + 手动排版出图          | 结构化简讯 + 模板一键出图               |
| 工具割裂   | 采集工具、编辑器、排版软件各一套       | 一个应用全流程闭环                    |
| 数据不在手  | 云端服务要登录、要付费、数据不归己      | 全本地，数据即文件                    |
| AI 协作难 | 想用 AI 帮忙分类摘要，但数据搬进搬出麻烦 | 简讯即 Markdown 文件，外部 AI 工具直接读写 |

### 1.4 产品愿景

让"采集 → 整理 → 出图"这条内容生产链路，**在一个本地工具里顺滑跑完**，同时保持对外部 AI 工具的开放协作能力。

---

## 二、产品核心

1. **全本地，数据归你**：所有采集、存储、处理、出图在本地完成，数据是可见的 Markdown 文件，不锁在任何云服务里
2. **AI 友好协作**：简讯以 Markdown 落地，外部 AI 工具可直接读写加工，应用不强绑特定 AI
3. **模板化出图**：所见即所得的 HTML/CSS 模板，适合移动端浏览的单页图
4. **属性驱动分流**：一条简讯按自定义属性自动分流到不同模板，一次生成多张不同风格的图
5. **零外部服务**：不用 Docker、不用数据库、不用服务器，装好即用

## 三、用户使用场景

### 3.1 场景一：游戏资讯每日汇总（主场景）

```
用户配置了 IGN、Eurogamer、Polygon 三个游戏新闻源
   ↓
工具每日 8:00 自动采集，生成 30 条简讯
   ↓
外部 AI 工具扫描简讯文件，自动生成摘要、判定"AB面"属性
   ↓
用户打开前端，快速浏览、修正个别分类
   ↓
用户选模板A + 筛选属性"面"
   → 面=A 的简讯 → 模板A 图（可分页生成多张）
   → 面=B 的简讯 → 模板B 图（可分页生成多张）
   ↓
导出多张图片，直接发布到社交平台
```

### 3.2 场景二：科技行业周报

```
配置 TechCrunch、Hacker News 等 RSS 源
   ↓
每周采集本周新闻
   ↓
AI 工具按"重要程度"打标（high/medium/low）
   ↓
选"周报模板" + 筛选 importance=high
   → 生成一张只含重要新闻的周报图
```

### 3.3 场景三：纯人工管理（不用 AI）

```
用户只配置 RSS 采集，不接入 AI
   ↓
采集后所有简讯在前端列表展示
   ↓
用户手动编辑每条简讯的摘要、标签、自定义属性
   ↓
选模板出图
```

## 四、功能需求

### 4.1 功能全景

```
mindmap
  root((ABSeek))
    采集管理
      采集源配置（RSS / 爬虫）
      定时调度
      健康状态监控
      试采集测试
    简讯管理
      简讯列表与筛选
      简讯编辑
      自定义属性管理
      状态流转
    AI 协作
      外部 Agent 文件接口
      协作规范文档
    图片生成
      模板管理
      模板预览
      属性分流生成
      批量导出
    系统设置
      代理配置
      去重规则
      日志
```

### 4.2 采集管理

#### F1：采集源配置

**描述**：用户可以添加、编辑、删除采集源，支持 RSS 与静态爬虫两种类型。

**需求点**：

- 每个采集源可配置：名称、类型、URL、采集频率、是否启用
- RSS 源：填写 RSS 地址即可
- 爬虫源：额外配置页面选择器（标题、链接、摘要等）
- 支持为采集源设置默认标签、默认分类
- 支持配置请求超时、重试次数、User-Agent

**验收标准**：

- 添加一个 RSS 源后，能在指定时间自动采集
- 可随时启用/停用某个源
- 配置错误时有明确提示

#### F2：定时调度

**描述**：按用户配置的频率自动触发采集。

**需求点**：

- 支持 cron 表达式（如每天 8:00、每小时、每周一）
- 多个源可独立调度
- 错过执行时间（如电脑关机）时的处理策略：下次启动补采/跳过

#### F3：采集源健康状态

**描述**：可视化展示每个采集源的运行状态。

**需求点**：

- 显示：上次采集时间、是否成功、连续失败次数、最近错误信息
- 显示：上次采集条数、新增条数
- 连续失败超阈值时高亮告警
- 采集日志可查看

**验收标准**：

- 用户一眼看出哪个源挂了
- 点击源可查看历史采集记录

#### F4：试采集测试

**描述**：配置采集源后，可手动触发一次测试采集。

**需求点**：

- 点击"测试连接"，立即拉取一次
- 返回：成功/失败、抓取条数、前 3 条样例数据
- 不写入正式简讯库，仅用于验证配置

**价值**：配置爬虫选择器时不用反复试错。

### 4.3 简讯管理

#### F5：简讯列表与筛选

**描述**：可视化展示所有简讯，支持多维筛选。

**需求点**：

- 列表字段：标题、摘要、来源、日期、标签、分类、自定义属性、状态
- 筛选维度：
  - 按日期范围
  - 按来源
  - 按标签
  - 按分类
  - 按自定义属性值
  - 按状态（raw/processed/reviewed/exported/archived/ignored）
- 排序：按日期、按来源、按状态
- 搜索：标题/摘要关键词
- 分页或虚拟滚动

#### F6：简讯编辑

**描述**：用户可对单条简讯进行二次加工。

**需求点**：

- 可编辑字段：标题、摘要、标签、分类、自定义属性、状态
- 保留原文/原摘要（便于校对 AI 翻译结果）
- 编辑后保存即写回文件
- 支持手动新增简讯
- 支持删除简讯（软删除/归档）

**验收标准**：

- 编辑后文件立即更新
- 前端列表实时刷新

#### F7：自定义属性管理

**描述**：用户可定义简讯的自定义属性 schema。

**需求点**：

- 属性键：如"面"、"重要程度"
- 属性值类型：枚举（固定可选值）
- 属性用于模板分流，是核心机制

**示例**：

- 属性"面"：可选值 A / B / C
- 属性"重要程度"：可选值 high / medium / low

**价值**：属性是连接"简讯"与"模板"的桥梁，决定了简讯最终进入哪张图。

#### F8：简讯状态流转

**描述**：简讯有明确的生命周期状态。

**需求点**：

- 状态：raw（原始）→ processed（已处理）→ reviewed（已审核）→ exported（已导出）
- 附加状态：archived（归档）、ignored（忽略）
- 用户可手动改状态
- AI 处理后自动置为 processed
- 导出图片后自动置为 exported

**价值**：清晰区分"未处理/已处理/已审核/已发布"，避免重复出图或漏处理。

### 4.4 AI 协作

#### F9：外部 Agent 文件接口

**描述**：应用以 Markdown 文件形式暴露简讯数据，外部 AI 工具可直接读写。

**需求点**：

- 每条简讯 = 一个 .md 文件（含 YAML frontmatter 元信息 + 正文）
- 文件按日期分目录存储
- 外部 AI 工具可：
  - 读取简讯文件
  - 生成摘要（写入 summary 字段）
  - 自动分类（写入 category）
  - 判定自定义属性（写入 customAttrs）
  - 翻译（保留原文，写中文到 title/summary）
- 应用通过文件监听感知 AI 的改动，前端自动刷新

**核心价值**：应用不强绑任何 AI，用户可用任意 agent 工具（命令行 LLM、本地大模型、云端 API 等）加工数据。

#### F10：协作规范文档

**描述**：应用自动生成一份给外部 AI 看的协作指南。

**需求点**：

- 首次初始化时生成 `AGENT_GUIDE.md`
- 内容包括：
  - 简讯目录结构
  - 文件命名规则
  - 字段说明与可修改权限
  - 状态流转规则
  - 写入规范（先写临时文件再重命名）
  - 示例

**价值**：用户把这份指南丢给 AI 工具，AI 就知道怎么规范地处理简讯文件。

### 4.5 图片生成

#### F11：模板管理

**描述**：用户可管理多套图片模板。

**需求点**：

- 每个模板 = 一个文件夹（HTML + CSS + 配置）
- 模板配置包括：
  - 名称、版本
  - 匹配属性（如"面"）与匹配值（如"A"）
  - 单图最多容纳简讯数（maxBriefs）
  - 超限策略（截断/分页/缩排）
  - 排序规则
  - 输出格式（JPG/PNG）、尺寸、文件名模板
- 模板可热加载，新增模板即加文件夹
- 区分内置模板与用户模板

#### F12：模板预览

**描述**：实时预览模板效果。

**需求点**：

- 用假数据（mock.json）预览，不依赖真实简讯
- 调整 HTML/CSS 后立即看到效果
- 所见即所得

**价值**：开发/调整模板时无需真实数据，快速迭代样式。

#### F13：属性分流生成

**描述**：核心生成机制——按自定义属性把简讯分流到不同模板。

**需求点**：

- 用户选一个筛选属性键（如"面"）
- 系统自动按该属性的不同值把简讯分组
- 每组对应一个模板（通过模板的 match 配置匹配）
- 一次操作生成多张图

**示例**：

- 选属性"面"
- 面=A 的 12 条简讯 → 模板A → 分页生成 3 张图
- 面=B 的 8 条简讯 → 模板B → 分页生成 2 张图
- 共导出 5 张图

#### F14：批量导出

**描述**：批量生成图片并导出。

**需求点**：

- 导出格式：JPG（默认，质量 90）/ PNG
- 尺寸：1080×1920（移动端竖屏，2x 高清）
- 分页时自动生成多张
- 导出后记录历史（哪些简讯已导出过）
- 导出路径可配置

**验收标准**：

- 导出的图直接可用于社交平台发布
- 文字清晰、不被平台压缩后糊掉

### 4.6 系统设置

#### F15：代理配置

**描述**：支持本机代理（如 Clash）以访问海外站点。

**需求点**：

- 三种模式：不使用代理 / 系统代理 / 手动配置
- 手动配置支持 http/socks5
- 提供"测试代理连通性"按钮

#### F16：去重规则

**描述**：避免同一新闻重复入库。

**需求点**：

- 多级去重：URL 规范化 + 内容哈希 + 标题相似度
- 去重保留期可配置（默认 30 天）

#### F17：日志

**描述**：记录各模块运行日志，便于排查。

**需求点**：

- 分模块日志：应用、采集、文件监听、图片渲染
- 按天滚动
- 前端可查看关键日志

## 五、非功能性需求

### 5.1 性能

| 指标              | 要求          |
| --------------- | ----------- |
| 采集 20 条 RSS     | < 15 秒（含代理） |
| 前端列表加载 1000 条简讯 | < 1 秒（虚拟滚动） |
| 单张图片生成          | < 5 秒       |
| 批量导出 10 张图      | < 30 秒      |

### 5.2 可靠性

- 采集失败不崩溃，记录错误并继续
- 文件解析失败不崩溃，移入异常目录并提示
- 外部 AI 写入异常文件不导致应用崩溃

### 5.3 数据安全

- 所有数据本地存储，不上传任何信息
- 简讯文件用户可见可备份
- 代理仅用于采集，不代理其他流量

### 5.4 可用性

- 安装即用，无需配置数据库/服务器
- 默认配置即可跑通主流程
- 关键操作有明确反馈（采集成功/失败、导出完成等）

### 5.5 合规性

- 仅用于个人信息整理
- 遵守目标站点服务条款与 robots 协议
- 优先使用 RSS，不绕过登录、不破解付费墙

### 7.2 v0.5 落地布局（已实现）

v0.5 将"简讯管理 + 模板预览 + 图片工作室"三者合并为单页双栏布局，降低页面跳转成本：

```
┌──────────────────────────────────────────────────────────────────────┐
│ ABSeek                                                               │
├──────────────────────────┬───────────────────────────────────────────┤
│ 左栏：简讯列表             │ 右栏：多模板并排预览                       │
│ ┌──────────────────────┐ │ ┌──────────────┐  ┌──────────────┐       │
│ │ 日期范围选择器         │ │ │ 模板A (A面)  │  │ 模板B (B面)  │       │
│ │ [今天/近7天/近30天/全部]│ │ │              │  │              │       │
│ └──────────────────────┘ │ │  缩略图预览   │  │  缩略图预览   │       │
│ ┌──────────────────────┐ │ │  (1080×1920) │  │  (1080×1920) │       │
│ │ Aspect 筛选: 全部/A/B │ │ │              │  │              │       │
│ └──────────────────────┘ │ │  分页 ◀ ▶    │  │  分页 ◀ ▶    │       │
│ □ 简讯1 [A] 标题         │ └──────────────┘  └──────────────┘       │
│ ☑ 简讯2 [B] 标题         │                                            │
│ ...                      │ 工具栏: 语言▾ | ⚙模板配置 | 导出图片       │
│ ─────────────────────── │                                            │
│ [移到A] [移到B] [编辑]   │ 编辑抽屉（点击✎ 或选中单条后"编辑"）        │
└──────────────────────────┴───────────────────────────────────────────┘
```

**与原 7.1 的差异**：

- 简讯管理、模板预览、图片工作室不再分页，合并为单页双栏
- 模板预览从"单模板切换"改为"按 default-bindings 并排多模板"
- 跨模板移动从"切标签 → 改属性"改为"选中简讯 → 点按钮 → 直接改 aspect"
- 简讯编辑从"主标签"降级为"右侧抽屉"（使用频率低）
- 模板配置从"设置页"上移到右栏工具栏（齿轮按钮）

### 7.3 核心交互流

**采集 → 出图主路径**：

```
采集配置页 →（等待采集）→ 简讯管理页 →（AI 处理 + 人工调整）
   → 图片工作室 →（选模板+属性）→ 预览 → 导出
```

**关键交互节点**：

- 简讯管理页是核心枢纽，所有数据在此汇总
- 图片工作室是产出终点，操作要尽量顺滑
- v0.5 简讯管理与图片工作室已合并，"选简讯 → 预览 → 导出"一气呵成

## 八、数据概念模型（产品视角）

> 注：此处仅描述产品层面的数据概念，技术实现见设计文档。

### 8.1 核心实体

| 实体    | 说明       | 关键属性                       |
| ----- | -------- | -------------------------- |
| 采集源   | 一个新闻来源   | 名称、类型、URL、频率、状态            |
| 简讯    | 一条新闻信息   | 标题、摘要、来源、日期、标签、分类、自定义属性、状态 |
| 自定义属性 | 简讯的可扩展属性 | 键名、可选值                     |
| 模板    | 图片样式模板   | 名称、匹配属性、匹配值、容量、超限策略        |
| 导出记录  | 一次导出操作   | 时间、模板、包含的简讯、产出文件           |

### 8.2 实体对应关系

```
采集源 1 ──── N 简讯
简讯   N ──── N 标签
简讯   1 ──── N 自定义属性（键值）
模板   1 ──── 1 匹配属性 + 匹配值   ←→  简讯的自定义属性值
导出记录 1 ──── N 简讯
导出记录 1 ──── N 产出文件
```

**最关键的关系**：模板通过"匹配属性 + 匹配值"与简讯的自定义属性值对应，实现分流。

### 8.3 术语定义补充

| 术语                 | 定义                                                      |
| ------------------ | ------------------------------------------------------- |
| 简讯（Brief）          | 一条结构化的新闻信息，是产品核心数据单元                                    |
| 采集源（Source）        | 一个新闻来源配置，如 IGN 的 RSS                                    |
| 模板（Template）       | 图片的样式定义，含 HTML/CSS 与配置                                  |
| 自定义属性（Custom Attr） | 简讯的可扩展属性，用于模板分流，如"面=A"                                  |
| 分流（Routing）        | 按属性值把简讯分配到对应模板的机制                                       |
| AB面                | 用户的自定义分类属性示例，将简讯分到模板A或模板B                               |
| 状态（Status）         | 简讯生命周期：raw/processed/reviewed/exported/archived/ignored |
| 分页（Paginate）       | 简讯数超过模板容量时，自动生成多张图                                      |
| frontmatter        | Markdown 文件顶部的 YAML 元信息块                                |
| AGENT_GUIDE        | 给外部 AI 工具看的协作规范文档                                       |
